
Git Usage
=========

git (classic)
_____________

1 Clone (initial) OR pull (update) repository (checkout)

cd cybop/build/
git clone https://github.com/EnricoGallus/CybopBuildScripts.git scripts

OR:

cd cybop/build/scripts/
git pull

2 Change AND save local source code

3 Push changes (checkin, publish)

git push

git (with GitHub)
_________________

1 fork project via web portal GitHub, to have it referenced in ones own user account
2 clone it to work locally with it
3 change it and and commit changes
4 push to remote GitHub repo
5 raise pull request to the owner via web portal GitHub
6 the owner will then decide if changes get integrated into the source

GitHub
______

https://stackoverflow.com/questions/5009600/difference-between-fork-and-branch-on-github

Repository (Repo):
- corresponds to the collaborated work of the team
- across one or many branches
- all contributors have their own copy of it

Fork:
- of the main repo corresponds to a contributor's work
- is really a GitHub (NOT Git) construct
- stores a clone of the repo in your user account
- as a clone, it will contain all the branches in the main repo at the time you made the fork

Branch:
- many branches may exist within a fork and/or in the main repo
- they can correspond to several kinds of things, depending on how you want to work
- could refer to a version of the project or different channels of development, like hotfixes or experimental work

Pull Request:
- corresponds to the task in the GitHub ecosystem
- to contribute an isolated finished task to the main repo
- corresponds to the commits made in that task
- these commits are pulled from either my fork or my branch to the main repo

Commit:
- a set of changes to the code
- one of the most interesting things about Git
- one does NOT transfer files, but logs of changes
